## 2. 踩过的坑

### 2.1 参考音尾音泄漏 → 每句开头多出「的是」

**症状**：50 句里 20 句（0.6B）开头多出 1~2 个字——
`的是 以前反变异工具…`、`大事 可人家不给圆满…`、`得失 到今天GitHub…`。

**定位过程**（三个假设，前两个都错了）：

| 假设 | 验证 | 结论 |
|---|---|---|
| ① 官方比例裁切算错 | 单独解码 ref_codes 得 222720 samples，比例切点也是 222720，**误差 0 sample** | ❌ 不成立 |
| ② 参考音 codes 掺进解码 | 用 `x_vector_only_mode=True`（完全不用 ref_codes），句首能量仍 −15.1dB | ❌ 不成立 |
| ③ 参考音在字中间被硬切 | 旧参考音**末采样 = 0.331**、最后 50ms 峰值 = 全曲 75% | ✅ 真因 |

**决定性对照**：官方示例 `clone.wav` 的**末采样 = 0.0000、最后 50ms 峰值 = 0%**，
用它克隆出来完全干净；而我们的片段结尾正好是「……却发生这样的事」被切断的「**的事**」，
被模型当作语气词带进了每一句。

**解法**：在词级时间戳里找**停顿处**收尾 → 15ms 余弦淡出 → 补 250ms 数字静音。

**效果**：句首多字 20/50 → **0/50**，CER 0.156 → 0.053。

> 判断只用 ASR 不可靠：Whisper 有时会把开头杂音吞掉，转写文本看起来是对的。
> **必须直接测参考音末采样幅度和末尾 200ms 峰值**。

### 2.2 逐句合成采样崩坏 → 成片音色突变（★ 最危险、最隐蔽）

**症状**：成片 01:16 处突然变成**男声**，与前后女声完全不搭，听感上像「换了个播音员」。

**实测数据**（第 21 条，`Ghidra 看程序，IDA、Hopper 看二进制，JADX 拆安卓包`）：

| 指标 | 正常句 | 第 21 条 | 判定 |
|---|---|---|---|
| `spk_cos` | 0.966~0.987 | **0.9202** | 偏低但没到崩 |
| `F0` 中位 | 316~338 Hz | **144.4 Hz** | **腰斩到 45%** |
| 局部 F0 | — | 0–1.2s: 122Hz / 1–2.2s: 148Hz / 2–3.2s: 157Hz | 整句都是男声 |
| 时长 | — | 5.68s（含 1.96s 溢出） | 恰好接近预估 |

**更明确的失控证据**：4~5.2s 处 ASR 识别出
**「中文字幕志愿者 李宗盛」**——这是**教科书式的重复循环/幻觉**症状。
模型在英文专名密度高的句子上失去了音色约束，开始生成与内容无关的语料。

**为什么没被拦住**（两个缺陷叠加）：

1. **旧的选择逻辑只看时长**：`cands.sort(key=lambda x: abs(x[0] - est))`——
   只挑「时长最接近预估」的候选，**从不校验音色**。崩坏的男声版本时长恰好最接近，于是胜出。
2. **初版阈值 0.90 太松**：0.9202 > 0.90，即使加了 cos 校验也会被放行。

**阈值必须落在实测空隙里**：

```
正常句 cos:  0.966 ~ 0.987
崩坏句 cos:  0.9202
         ↑ 0.90 在这里（放行）
              ↑ 0.95 在这里（拦截）
```

**最终解法（三道防线）**：

```python
# ① token 封顶：防重复循环无限生成
tok_cap = max(160, int(est * 12.5 * 1.7))

# ② 截断判定：用满上限 = 大概率在循环
if dur >= (tok_cap / 12.5) * 0.92:
    continue

# ③ 音色 + 音高双校验：换人了就必须重采
good = cos >= 0.95 and f0 >= ref_f0 * 0.75
```

**重采有效性实测**：同一句、同参数、换 seed 连采 6 次：

| try | dur | cos | F0 | 判定 |
|---|---|---|---|---|
| 0 | 5.68 | 0.9201 | 144.4 | ❌ 男声 |
| 1 | 4.80 | **0.9755** | **316.8** | ✅ 可用 |
| 2 | 5.68 | 0.9473 | 273.5 | ❌ |
| 3 | 5.60 | 0.9488 | 232.0 | ❌ |
| 4 | 5.12 | **0.9750** | **327.8** | ✅ 可用 |
| 5 | 4.88 | 0.9544 | 276.1 | ❌ |

**约 1/3 的采样是好的**，所以重采 4~5 次基本必中。
别因为「第一次崩了」就以为模型不支持这句话。

**修复后**：全篇 50 句 cos 最低 **0.9660**、F0 全部落在 **292.8~351.7 Hz**，
最大溢出从 +1.96s 降到 **+0.81s**（因为换掉了那个异常偏长的男声版本）。

**易触发崩坏的文本特征**（经验）：
- 英文专名密度高：`Ghidra / IDA / Hopper / JADX / MCP`
- 数字与中英混排：`HR 1.01`、`24.9 万`
- 书名号/引号密集：`《大富翁 4》`、`"会提问的普通人"`

> **结论：音色一致性必须做逐句校验，不能抽样。**
> 这类崩坏在时长维度上完全看不出问题，只有 F0 会立刻暴露。

### 2.3 `max_new_tokens` 默认 8192 → 合成「卡死」

**症状**：批量合成跑到第 12 条后几分钟没动静，GPU 利用率 50% 左右、CPU 持续增长，
看起来像死锁，其实在拼命生成。

**原因**：`generation_config.json` 里 `max_new_tokens: 8192`，
按 12.5 token/秒换算 ≈ **655 秒音频**。采样一旦进重复循环，就会一路生成到上限。

**解法**：按句子长度封顶。

```python
est = max(chars / 6.0, 1.2)          # 按 6 字/秒估
tok_cap = max(160, int(est * 12.5 * 1.7))
```

> 复现要点：单独跑那一条往往正常（seed 不同），
> 只有连续批量时才撞上——所以「单条测试通过」不能证明批量没问题。

### 2.4 torch 装成 CPU 版（静默降级）

**症状**：`torch.cuda.is_available()` 为 False，`torch.__version__` 显示 `+cpu`。

**原因**：`uv pip install torch --index-url .../cu128` 时，
如果 cu128 索引里**没有**最新版本，uv 会回退到 PyPI 的 CPU 轮子，而且**不报错**。
实测 cu128 最高只到 2.9.1，而 PyPI 已有 2.14.1 → 装了 `2.14.1+cpu`。

**解法**：用直链锁定 CUDA 轮子。

```bash
uv pip install --no-deps \
  "https://download.pytorch.org/whl/cu128/torch-2.9.1%2Bcu128-cp312-cp312-win_amd64.whl" \
  "https://download.pytorch.org/whl/cu128/torchaudio-2.9.1%2Bcu128-cp312-cp312-win_amd64.whl"
```

装完必须验证：

```python
import torch
assert torch.cuda.is_available()
assert torch.cuda.get_device_capability(0) >= (8, 0)   # bf16 需要 ≥ 8.0
```

### 2.6 8GB 显存：TTS 与 ASR 不能同时驻留

**症状**：批量评测跑几条后 `CUDA failed with error out of memory`。

**原因**：1.7B TTS（3.9GB）+ Whisper large-v3（约 3GB）> 8GB。
且 `asr()` 若每条都新建 `WhisperModel(...)`，会反复占显存。

**解法**（两段式 + 单例）：

```python
# 阶段 1：算完全部 speaker embedding
sims = [cos(ref_e, spk_emb(model, p)) for p in paths]
# 阶段 2：释放 TTS 再跑 ASR
del model; gc.collect(); torch.cuda.empty_cache()
```

**实测**：释放后空闲 6.91 / 8.00 GB，足够 Whisper large-v3。

### 2.7 `voice_timeline.js` 是单文件覆盖

**症状**：换引擎重配音后，旧版成片的时间轴再也找不回来了。

**原因**：`tts_voiceover.py` 每次都会**整份重写** `<project>/voice_timeline.js`。

**解法**：换引擎前备份，或从 `align_report.json` + `voice_new.srt` 反推还原。

```bash
cp voice_timeline.js voice_timeline.<旧引擎>_backup.js
```

> 同理：`video_voice.html` 读的是这一份文件，
> 所以「换配音」和「改画面」共用同一条时间轴，必须一起重新渲染。

### 2.8 `render.js` 的关键帧签收门禁

**症状**：全量渲染直接报「没有有效签收」，或渲出来跑的是旧时间轴。

**两个独立原因**：

1. **签收目录名对不上**：`render.js` 的 `--review-dir` 默认 `./keyframes`，
   若签收在 `./keyframes_voice`，必须显式传：
   ```bash
   node render.js ... --review-dir ./keyframes_voice
   ```
2. **改过 js 后签收失效**：签收绑定工程指纹，改任何 js/html 都要重新出帧审查。
   `voice_timeline.js` 变了 → 指纹变了 → 必须重新 sign off。

### 2.9 质检别只信 ASR

本轮三处「ASR 会说谎」的实例：

| 实例 | ASR 表现 | 实际情况 |
|---|---|---|
| 参考音尾音泄漏 | 把开头的「的是」**吞掉**，转写文本干净 | 音频有杂音 |
| 男声崩坏 | 文字内容**识别正确**，只是音色全错 | 音色已崩 |
| 崩坏导致的幻觉 | 吐出「请不吝点赞…」「中文字幕志愿者 李宗盛」 | **是幻觉，不是源文本**（详见 §3.5） |

第三类最危险：幻觉出来的文字**看起来像真的内容**（尤其是模板残留这种常见错误），
会把人引去改一份没问题的字幕稿。

**可靠做法是分层校验**：

| 层次 | 手段 | 抓什么 |
|---|---|---|
| 波形 | 末采样 / 峰值 / RMS | 参考音质量、静音、削波 |
| 说话人 | `spk_emb` 余弦 | 音色漂移 |
| 音高 | `F0` 中位数 | **换性别/换音域**（ASR 完全看不出） |
| 文本 | ASR 回环 CER | 吐字、幻觉（**只作一致性探测，不作事实来源**） |
| 时间 | `align_report.json` 的 `overflow` | 时长失配、溢出 |

**判读规则**：`CER` 接近 1.0 → 先查音频，别先查稿子；
要确认源文本对不对，直接读 SRT 或 `align_report.json` 的 `text` 字段。

## 3.5 ⚠️ 反面教训：被 Whisper 幻觉误导，差点改了没问题的字幕稿

**背景**：修复前跑评测，输出里有这么一行：

```
cue_022.wav  spk_cos=0.981  CER=1.000  请不吝点赞 订阅 转发 打赏支持明镜与点点栏目
```

**错误结论**：我据此向用户报告「SRT 第 22 条文本是『请不吝点赞…』，与主题不符，
像是模板残留，建议删掉」，还补了一句「两个模型都照念了」。

**真相**：原 SRT 第 22 条是

```
Ghidra 看程序，IDA、Hopper 看二进制，JADX 拆安卓包
```

完全没有「请不吝点赞」。那段文字是 **Whisper 对崩坏男声音频产生的幻觉**——
`请不吝点赞订阅转发打赏…` 是中文 ASR 语料里极高频的句式，模型在遇到无法识别的
音频时会往这个方向硬凑。`CER=1.000`（完全不相交）本身就是「音频有问题」的强烈信号，
而不是「字幕稿有问题」的证据。

**两个教训**：

1. **`eval` 输出里的 `asr` 字段是「生成音频的再转写」，不是源文本**。
   要判断源文本错没错，必须直接读 SRT / `align_report.json` 的 `text` 字段。
2. **`CER` 接近 1.0 时先怀疑音频，不要先怀疑稿子**。
   同一条 cue 在不同 run 里还幻觉出过「中文字幕志愿者 李宗盛」（见 §2.2），
   两次幻觉内容不同——模板残留不会这样随机变。

> 这条和 §2.9 是同一个根因：**把 ASR 输出当成事实来源**。
> ASR 在这个流程里只适合当「一致性探测器」，不能当「真相来源」。

## 4. 已知限制

| 限制 | 说明 | 缓解 |
|---|---|---|
| 长文本漂移 | 单句越长越容易在句中失稳 | 按 SRT 逐句合成，别整篇一次生成 |
| 英文专名 | 易触发音色崩坏（见 §2.2） | 重采 + 校验；必要时给中文注音 |
| 语速不可精确控制 | Base 模型无 instruct 能力，语速靠参考音携带 | 换参考音（选语速接近的片段），或 atempo 后处理 |
| 音色相似度天花板 | 实测 0.97~0.99，不等于原人 | 这是零样本克隆的常态，不追满分 |
| 8GB 显存 | 1.7B + Whisper 不能共存 | 分段执行 |
