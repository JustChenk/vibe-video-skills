# 呈现原则：什么时候该动，什么时候该直接给

> 两条来自实战的硬原则。违反它们的视频，观众会觉得「慢」「赶」「读不完」。
> 核心判据只有一个：**这个元素是让人"读"的，还是让人"感知"的？**

---

## 一、第一条：文字直接呈现，不逐字蹦

### 问题

逐字打字机（typewriter）看起来有仪式感，实际制造两个硬伤：

1. **音画必然不同步**。配音按 SRT 每个槽位整句念，画面却还在一个个蹦字。一句 20 字的字幕，语音 4 秒念完，打字机要 3 秒才出齐——前 3 秒观众听到的和看到的不一致。后期加配音时这是无法调和的矛盾。
2. **有效阅读时间被削掉**。观众必须等字出完才能读整句，而它本该在出现的第一帧就可读。

### 规则

| 元素 | 呈现方式 |
|---|---|
| 字幕 | **整句贴上去**，0.14s 淡入 |
| 大标题 | **整块淡入 + 6px 上浮**，不逐行不逐字 |
| 表格 | **整表一次给出**，不逐行翻阅 |
| 说明行 / 批注 / 页脚 | 直接完整 |

代码上就是：**不用 `typed()`，用 `alpha` 淡入**。

```js
// ✗ 逐字
ctx.fillText(typed(text, clamp01(p * 3.0)), x, y);

// ✓ 直接完整
ctx.globalAlpha = clamp01(p * 7);   // 0.14s 淡入
ctx.fillText(text, x, y);
```

**字幕衬底也要跟着改**：宽度按**整句**测量，不能随字数增长（否则会看到纸条一边变长一边长字）。

### 例外

极少数需要"逐字涌现"仪式感的场合（比如一行诗、一个判决结果），可以保留 `typed()`。但**每集最多一处**，且必须是不配音的纯画面上。

## 二、第二条：并列信息整组给，递进信息才逐条

### 问题

「每张卡片间隔 0.9 秒依次落地」在演示里很漂亮，在成片里就是**让观众干等**。如果五张卡片是并列关系（五个部分、三条理由、三条路径），观众从第一张落下的瞬间就已经想读完所有内容，却要等到第 5 秒。

### 规则

先判断这组元素的**逻辑关系**：

| 关系 | 判据 | 入场方式 |
|---|---|---|
| **并列** | 换个顺序意思不变 | **整组一次给出**（一个 `p` 控制全部） |
| **递进** | 顺序有意义（时间线、因果、步骤） | 逐条入场，间隔 0.6–1.0s |
| **对抗** | 左右对比，需要"先看到 A 再看到 B" | 错开 0.6–0.8s（**这个必须错开**，否则像列表不像对比） |

### 典型判断

| 场景 | 关系 | 做法 |
|---|---|---|
| 五个部分（为什么/谁付代价/落到哪/怎么扛/往哪走） | 并列（顺序只是习惯） | 整组一次 |
| 三条观看路径（完整线/求职者线/行业线） | 并列 | 整组一次 |
| 三条理由（东亚第一个/走过的路/时间刻度） | 并列 | 整组一次 |
| 1989 vs 1999 双卡对比 | **对抗** | 错开 0.8s |
| 时间轴上的事件节点（1993→1997→2003） | **递进** | 逐个出现 |
| 三步走战略（产业→全链条→文化） | **递进** | 逐条出现 |

### 代码

```js
// ✗ 并列却逐条
nodes.forEach((nd, i) => {
  const p = A.pg(t, 2.0 + i * 0.9, 2.9 + i * 0.9);   // 每张自己算时间
  A.block(ctx, ..., { p });
});

// ✓ 并列整组
const pGroup = A.pg(t, 1.5, 2.1);
nodes.forEach((nd, i) => {
  A.block(ctx, ..., { p: pGroup });                   // 共用一个进度
});
```

## 三、什么该保留动效

动效用在该用的地方——**让观众感知"物件被放上来"**，而不是"文字被打印出来"。

| 保留动效 | 理由 |
|---|---|
| 档案袋抽出 | 系列仪式，建立"这一集是一份卷宗" |
| 卡片贴上（旋转归位） | 模拟真实粘贴，有质感 |
| 印章盖下（1.18→1.0 回弹） | 全片情绪落点，必须有重量 |
| 时间轴生长 | 建立"历史展开"的感知 |
| 下划线划出 | 模拟"读到这句才划重点" |
| 对抗组的错开 | 让对比关系成立 |

| 不要动效 | 理由 |
|---|---|
| 文字逐字 | 音画不同步 + 削阅读时间 |
| 表格逐行 | 表格的本质是"一眼扫完" |
| 并列组逐条 | 让观众干等 |
| 淡入淡出转场 | 纸面风格靠"抽换纸张"，不靠溶解 |

## 四、自检清单

做完一集，逐条过：

- [ ] 全片没有 `typed()` 调用（字幕、标题、表格、批注）
- [ ] 字幕衬底宽度按整句算，不随字增长
- [ ] 所有并列信息组共用一个进度变量
- [ ] 对抗组（左右对比）错开 0.6–0.8s
- [ ] 递进组（时间线、步骤）逐条但间隔 ≤1.0s
- [ ] 印章 / 档案袋 / 时间轴 / 下划线保留了动效
- [ ] grep 检查：`grep -c "typed(" scenes.js` 应为 0

## 五、这两条原则背后的同一件事

**动效是给"感知"用的，不是给"信息"用的。**

观众看视频时有两套处理系统：
- 读文字 —— 越快到位越好，任何延迟都是负担
- 感知动作 —— 需要时间才能感受到"重量""粘贴""盖下"

把这两件事混在一起（文字也做动效），就会两边都不讨好：文字读得慢，动作也不够有分量。

**克制地使用动效，反而让保留动效的地方更有力量。** 全片只有印章是真正"盖下去"的，它才显得重。
