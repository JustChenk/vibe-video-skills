# 导师手册：把剩下 16 集交给别人做，怎么保证不走样

> 本文件写给**系列负责人（导师）**：你自己做完了样板集，剩下的集要分派出去。
> 核心不是"写一份很长的任务书"，而是**设计一个验收闭环**——让偏离在渲染之前就被拦住。

---

## 一、先明确分工：什么必须自己做，什么可以派

| 环节 | 谁做 | 为什么 |
|---|---|---|
| 系列规划、风格总纲、集目清单 | **导师** | 决定整个系列的方向，派出去就散了 |
| 样板集（第 1 集） | **导师** | 它定义了"合格"的标准，不能由被验收者定义 |
| 单集调研（查数据、核勘误） | 可派 | 工作量最大，但标准明确（三层溯源） |
| 单集分镜（8 幕设计） | 可派，**导师审** | 分镜决定内容质量，必须过目 |
| 工程实现（写 scenes.js） | 可派 | 有引擎兜底，形态受限 |
| 关键帧审查 | **导师或第二个 Agent** | 自己审自己的画面等于没审 |
| 成片验收 | **导师** | 终验必须独立复跑 |

**一句话**：**方向和验收不能派，执行可以派**。

---

## 二、派单任务书必须含的六件事

被派单的可能是人，也可能是模型。它**看不到你的上下文**，所以任务书必须自包含：

### 1️⃣ 绝对路径，不要相对路径

```
✗ "参考 Ep00 的 scenes.js"
✓ "参考 D:\...\以日为鉴\Ep00-一个国家的错题本\scenes.js"
```

模型的工作目录可能与你不同。相对路径是最高频的失败原因。

### 2️⃣ 必读文件清单（按顺序）

```
1. <系列>/系列风格总纲.md          ← 风格规则
2. <系列>/Ep00-*/运镜与制作思路.md  ← 为什么这么设计
3. <系列>/Ep00-*/archive.js        ← 有哪些组件可用
4. <系列>/Ep00-*/scenes.js         ← 实现长什么样
5. <系列>/原书/全文/NN-*.md         ← 本集素材
```

**顺序不能反**：先规则、再理由、再工具、最后示例。反过来会让人先抄形式、不理解约束。

### 3️⃣ 本集的具体输入

- 章节原文路径
- 素材分级（A/B/C）与是否扩展
- 勘误台账里涉及本集的条目（**直接抄进任务书**，不要让被派单者自己去翻）
- 回指上一集的**具体那句话**（你写好，不要让它编）

### 4️⃣ 硬性禁止项（越具体越好）

```
✗ 不要手写色值（一律 A.C.xxx）
✗ 不要手写字幕坐标（一律 A.subtitle）
✗ 不要手写说明行坐标（一律 A.takeaway）
✗ 不要自创动效（只能 stamp / typing / sticker / paperSlide）
✗ 不要在第 1 秒留空画面
✗ 不要大段照搬原文（单集引用 ≤ 全片字幕 15%）
```

### 5️⃣ 交付物清单

```
□ scenes.js（本集内容）
□ framework.js 的 SCENES 数组（改 start/dur/name）
□ 字幕.srt（voice-ready）
□ 视频分镜脚本.md
□ 运镜与制作思路.md
□ 成片.mp4（无声母版）
```

### 6️⃣ 自检要求 + 汇报格式

```
自检必做：
- precheck 0 ERROR
- keyframes 出帧后逐张 Read（不能只看机械体检）
- encode 后 grab 抽帧与审查帧比对

汇报格式：
- 8 幕各一句话
- 字幕条数 / 总字数 / 语速区间
- 发现的数字矛盾（如有）
- 遗留问题
```

## 三、验收闭环：四道闸门

派单不是"给他做"，是"给他做 + 设四道门"。

### 闸门 1 · 分镜预审（渲染之前）

**时机**：对方交了分镜脚本，还没写代码。

**查什么**：
- 8 幕是否各有**独立的作用**？（不能有两幕在做同一件事）
- 每幕的**朱红焦点**是什么？说不出来就是没设计
- 时间轴点亮哪一段？和本章内容对得上吗？
- 字幕总字数是否在 600–700？（超了说明塞太多）
- 回指和预告的**具体句子**写了吗？

**这一关最省成本**：分镜错了，改文档 10 分钟；做完再改，重渲 3 分钟 + 重审 24 帧。

### 闸门 2 · 静态自检（代码写完）

```bash
node precheck.js scenes.js archive.js framework.js
```

**查什么**：退出码是否为 0。

**注意**：precheck 只能证明"代码没写错"，证明不了"画面对"。它拦得住参数错位、SCENES 时间轴不连续、场景函数没定义；拦不住叠字、元素互压、语义错位。

### 闸门 3 · 关键帧视觉审查（**核心闸门**）

```bash
node keyframes.js video.html keyframes --srt 字幕.srt --dur 160
```

**流程**：
1. 先看 `_联系表.jpg`（一张图看全片，找明显异常）
2. 对可疑幕逐张放大 Read
3. 机械体检的 ERROR 必须清零；WARN 要能说出理由
4. `--approve` 签收

**签收的机制价值**：签收记录里绑了**工程指纹**（html + js 的内容哈希）。对方签收后再改一行代码，签收自动作废，render 会拒绝渲染。**这防止了"审的是 A 版，渲的是 B 版"**。

**导师要做的**：不是重跑一遍，而是**抽查签收记录是否存在 + 抽 2-3 帧自己看**。如果对方说"审过了"但没有签收文件，视为没审。

### 闸门 4 · 成片终验（独立复跑）

不要照抄对方的汇报，自己跑：

```bash
# 规格
ffprobe -v error -select_streams v:0 -show_entries stream=width,height,r_frame_rate,codec_name,nb_frames -of csv=p=0 成片.mp4
ffprobe -v error -show_entries format=duration -of csv=p=0 成片.mp4

# 抽帧
node grab.js 成片.mp4 8 20 43 69 105 146 156
```

**查什么**：

| 项 | 判据 |
|---|---|
| 尺寸 | 1920×1080 |
| 帧率 | 24/1 |
| 编码 | h264 |
| 帧数 | = 时长 × 24（差 1 帧也要查） |
| 音轨 | 无（母版阶段） |
| 抽帧 | 与 keyframes 的审查帧一致 |
| 硬数字 | 与调研材料逐项对照 |

**最后一项最重要**：把成片里的每个数字抄下来，和 `调研材料.md` 的数据表逐条对。这一步人工成本高，但**只有它能拦住"数字写错"**。

## 四、常见偏离与处理

| 症状 | 根因 | 处理 |
|---|---|---|
| 字幕和说明行叠在一起 | 手写了坐标 | 打回，要求一律用 `A.takeaway` / `A.subtitle` |
| 每幕内容太长读不完 | 字幕超 28 字 / 语速 > 5.5 | 打回，要求按 5.0 字/秒重配 |
| 画面像 PPT | 没有母题（时间轴缺席） | 打回，每幕必须调 `A.timeline` |
| 动效花哨 | 自创了 fadeIn / flyIn | 打回，只能四个白名单动作 |
| 色值不一致 | 手抄了十六进制 | `grep -E "#[0-9A-Fa-f]{6}" scenes.js`，有命中就打回 |
| 数据对不上 | 没回原文核 | 打回，要求逐条标出处小节 |
| 前 1 秒空白 | 内容入场太晚 | 打回，第一块内容必须在 0.3s 内出现 |

## 五、并行派单的注意事项

### 5.1 一次 2–3 集

全量渲染阶段抢 CPU，4 集以上会明显降速。而且验收带宽有限——**你能认真看的量就是你能派的量**。

### 5.2 并行期间禁止目录手术

不要在被派单者运行时重命名/移动/删除任何目录。空目录会被当成垃圾清掉，路径引用会断。

### 5.3 每集封闭在自己的文件夹

被派单者只读写 `<系列>/EpXX-主题/`。**不许改 `archive.js` / `framework.js`**——那是跨集共用的，改一次全系列漂移。

**如果确实需要新组件**：让它在 `scenes.js` 里写局部 helper，验证好用后由**导师**合并进 `archive.js` 并升版本号。

## 六、给"学生"的一段话（可直接转发）

> 你要做的这一集，不是"再做一个视频"，是**让观众看完想去读那一章**。
>
> 开工前先做三件事：
> 1. 读 `系列风格总纲.md`，知道这套画风的红线在哪
> 2. 读样板集的 `运镜与制作思路.md`，知道为什么那么设计
> 3. 读本章原文，把 6–12 个硬数字抄出来（标清楚在哪一节）
>
> 然后写分镜：8 幕，每幕 12–28 秒，每幕一个朱红焦点，每幕一句话说清它在干什么。
>
> **写不出"这一集让观众学会什么"这一句话，就别开始写代码。**
>
> 代码阶段只做三件事：调组件、给内容、算进度。不要重新发明组件，不要手写色值，不要手写坐标。
>
> 做完必须跑 keyframes 并**逐张看图**。机械体检通过不代表画面对——它拦不住叠字和错位，只有眼睛能。
>
> 交付时告诉我：8 幕各一句话、字幕字数、你在原文里发现的数字矛盾。
