# 模板示例：一个已完成的样板集长什么样

> 本文件是 `series-video-planner` 的**可复制样板**说明。配套的真实工程在《以日为鉴》系列的 `Ep00-一个国家的错题本/`。
> 用途：接手者先看这里知道「一套完整的集目录应该有什么」，再去读真实工程。

---

## 一、一个完整的集目录

```
EpXX-主题/
├── video.html                     # 入口：依次加载 引擎 → 场景 → 框架
├── archive.js                     # 风格引擎（跨集共用，通常不改）
├── framework.js                   # 主框架（跨集共用，只改 SCENES 数组）
├── scenes.js                      # 本集内容（唯一需要大改的文件）
├── 字幕.srt                       # voice-ready，后期配音直接吃
├── 调研材料.md                     # 核心问题 / 硬数字表 / 金句 / 勘误
├── 视频分镜脚本.md                  # 每幕一行：时间码 / 画面 / 字幕
├── 运镜与制作思路.md                # 为什么这么画（给接手者看）
├── keyframes/                     # 审查帧 + 联系表 + 签收记录
├── grab/                          # 成片抽帧复核
├── frames/                        # 全量渲染帧（可删，约 1-2GB）
└── 成片.mp4                       # 无声母版
```

**三个"必须同时存在"的文档**：`调研材料`（数据从哪来）、`分镜脚本`（画什么）、`制作思路`（为什么这么画）。少最后一个，接手者只能看到"结果"看不到"决策"，风格就会漂。

## 二、`video.html`（约 20 行，不用改）

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head><meta charset="UTF-8"><title>系列名 · 集名</title>
<style>
  html,body{margin:0;padding:0;background:#111;overflow:hidden;height:100%}
  #wrap{position:absolute;inset:0;display:flex;align-items:center;justify-content:center}
  #stage{display:block;max-width:100%;max-height:100%;background:#E8DFC8}
</style></head>
<body>
<div id="wrap"><canvas id="stage" width="1920" height="1080"></canvas></div>
<script src="archive.js"></script>
<script src="scenes.js"></script>
<script src="framework.js"></script>
</body>
</html>
```

**顺序不能变**：`archive.js`（定义 `window.A`）→ `scenes.js`（定义 scene 函数）→ `framework.js`（注册 SCENES 并启动渲染）。

## 三、`framework.js` 里唯一需要改的部分

```js
const SCENES = [
  {start: 0.0,   dur: 12, draw: typeof scene1 !== 'undefined' ? scene1 : () => {}, name: 'S1 抽档'},
  {start: 12.0,  dur: 18, draw: typeof scene2 !== 'undefined' ? scene2 : () => {}, name: 'S2 钩子'},
  {start: 30.0,  dur: 24, draw: typeof scene3 !== 'undefined' ? scene3 : () => {}, name: 'S3 破题'},
  // ... 后一幕 start 必须 == 前一幕 start + dur
];
```

**硬约束**：
- `start` 必须首尾相接（`precheck.js` 会报错）
- 总时长 ≤ 180s（超了 precheck 报错）
- 每幕 12–28s（低于 12s 观众读不完字幕，高于 28s 注意力会走）

## 四、`scenes.js` 的标准写法

每个 scene 函数**只做三件事**：调组件、给内容、算进度。

```js
function scene2(ctx, t, L) {
  // 1) 母题：一行搞定，不写坐标
  A.timeline(ctx, { grow: 1, active: [1990, 2010] });

  // 2) 内容：组件 + 参数
  const p2 = A.pg(t, 0.10, 1.40);      // 进度 0→1，区间是「幕内秒数」
  A.block(ctx, 150, 170, 700, 300, {
    p: p2, rot: -0.8,
    head: '1989', headSize: 88,
    sub: '东京地价买下整个美国\n日经指数 38,957 点', subSize: 27,
  });

  // 3) 固定版式：说明行与字幕（不接受坐标参数）
  A.takeaway(ctx, '这本书要回答的就是：这十年里，选择是怎么一步步做错的', A.pg(t, 5.0, 6.2));
  A.subtitle(ctx, '同一个国家，十年之间从买下美国到僵尸企业遍地', A.pg(t, 0.6, 17.0));
}
```

### 组件速查表

| 组件 | 用途 | 关键参数 |
|---|---|---|
| `A.paper(ctx)` | 纸底（已由 framework 调用） | — |
| `A.header(ctx,l,r,a)` | 页眉（已由 framework 调用） | 左系列名、右卷宗号、alpha |
| `A.timeline(ctx,opt)` | **40 年时间轴**（每幕必调） | `grow` 生长进度、`active:[y0,y1]` 点亮段、`marks` 事件节点 |
| `A.card(ctx,x,y,w,h,o)` | 空白贴纸卡 | `rot` 倾斜、`p` 入场、`fill` |
| `A.dossier(ctx,x,y,w,h,o)` | 档案袋（含装订孔+标签） | `big` 大编号、`sub` 标签字 |
| `A.stamp(ctx,text,x,y,size,rot,p)` | 朱红印章 | `text` 2–4 字、`rot` 默认 -3° |
| `A.title(ctx,lines,x,y,size,o)` | 大标题（多行硬碰） | `lines` 数组、`align` |
| `A.line(ctx,text,x,y,size,o)` | 单行文字 | `p` 打字机、`family` serif/sans/mono |
| `A.table(ctx,x,y,w,head,rows,o)` | 表格（数字入表） | `hot` 高亮行索引、`colW` 列宽比 |
| `A.block(ctx,x,y,w,h,o)` | 卡片+标题+小字（最常用） | `head` 主字、`sub` 说明、`red` 朱红竖条 |
| `A.annot(ctx,text,x,y,size,o)` | 手写批注 | `rot` 倾斜 |
| `A.underline(ctx,x,y,w,p,c)` | 划重点线 | — |
| `A.connector(ctx,x1,y1,x2,y2,p,o)` | 虚线连接 | `dash` 虚线样式 |
| `A.subtitle(ctx,text,p,o)` | **字幕**（坐标内置） | `stamp:true` 盖章式出现 |
| `A.takeaway(ctx,text,p,o)` | **说明行**（坐标内置） | — |
| `A.footer(ctx,text,p)` | 页脚署名 | — |

### 进度函数

```js
A.pg(t, a, b)   // t 在 [a,b] 区间内的进度，钳在 0–1
A.E.outCubic(u) // 缓动
```

**`a`、`b` 是幕内秒数**（因为 framework 传给 scene 的是 `local`，不是全局 `t`）。

## 五、分镜脚本的格式（每集一份）

```markdown
# EpNN《片名》分镜脚本

> 总时长 160s · 8 幕 · 1920×1080 @24fps · 无音轨
> 钩子类型：反常识断言
> 数据基准：本目录《调研材料.md》
> 素材分级：A（不扩展）

| 时间码 | 幕 | 画面要点 | 字幕金句 |
|---|---|---|---|
| 00:00–00:12 | S1 | 档案袋落下 + 标题 + 时间轴生长 | （见字幕.srt 第 1 条） |
| 00:12–00:30 | S2 | 1989/1999 双卡对比 + 朱红断言 | … |
| ... | | | |

## 系列元素（每集固定）
1. 片头：时间轴点亮本集年段（2s）
2. 回指：第 2 幕一句「上一集说过……」
3. 片尾：下一集片名 + 一句话

## 制作红线
- 不得上屏：<从勘误台账抄过来>
- 作者主张必须标「作者认为」：<列出>
```

## 六、制作思路文档的格式（每集一份）

这是**最少人写、但最重要**的一份。结构：

```markdown
# EpNN《片名》运镜与制作思路

## 一、这一集的定位
一句话让观众学会什么；它不是 X，它是 Y。

## 二、节奏设计
总时长 / 幕数 / 字幕字数 / 语速；每幕的呼吸节奏。

## 三、八幕拆解
逐幕：画面是什么 → 为什么这么画 → 运镜细节（参数）→ 字幕与画面的分工。

## 四、视觉母题的使用频率
哪个母题在哪几幕出现，为什么不在所有幕出现。

## 五、踩过的坑
真实教训，写清楚症状 + 根因 + 修法。
```

**第 5 节最值钱**：它把"排错经验"传给下一个人。没有这一节，接手者会把同样的坑再踩一遍。

## 七、完整的制作命令序列

```bash
NODE="C:/Users/yangck/.workbuddy/binaries/node/versions/22.22.2-6/node.exe"
S="<skill>/scripts"

# 1. 静态自检（参数是 js 文件，不是 html！）
"$NODE" $S/precheck.js scenes.js archive.js framework.js

# 2. 出审查帧（每幕 3 张 + 每条字幕 1 张）+ 联系表
"$NODE" $S/keyframes.js video.html keyframes --srt 字幕.srt --dur 160

# 3. 逐张 Read 审查帧 / 先看 _联系表.jpg 再放大可疑幕
#    ⚠️ 这一步不能省，也不能只看机械体检结果

# 4. 签收（写死工程指纹）
"$NODE" $S/keyframes.js video.html keyframes --approve "逐张看过，无错位"

# 5. 全量渲染（无签收会被拒绝）
"$NODE" $S/render.js video.html frames --fps 24 --dur 160 --clean

# 6. 编码
"$NODE" $S/encode.js frames 24 "成片.mp4" 4.5M

# 7. 成片抽帧复核（与审查帧比对）
"$NODE" $S/grab.js "成片.mp4" 8 20 43 69 105 146 156
```
