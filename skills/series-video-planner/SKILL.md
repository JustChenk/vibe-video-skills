# Series Video Planner（大主题 → N 集系列视频）

## Overview

一段万字长文、一个大专题或一本二十万字的书，一集讲不透，按章节机械切又会碎。本 skill 提供一套经过实战验证的拆分逻辑：**判体量 → 定风格总纲 → 按认知弧重组 → 定链接强度 → 落系列规划 → 逐集制作与验收**，最终得到一套"单集可独立看懂、合起来是完整体系、画风从头到尾是同一个人做的"的视频合集。

单集生产本身不在本 skill 范围（走 `handdrawn-explainer-video` / `dark-field-explainer-video` 或系列自建风格），本 skill 管的是**"集以上"的所有决策与协作模式**。

## 配套 skill（同属 vibe-video-skills 合集仓库）

| 阶段 | Skill | 干什么 |
|---|---|---|
| ① 拆集 + 定风格 | **`series-video-planner`（本 skill）** | 体量判断 → **风格总纲** → 拆分逻辑 → 链接强度 → 系列规划.md |
| ② 制作 | `handdrawn-explainer-video` / `dark-field-explainer-video` | 每集的调研/分镜/动画/自检/渲染/交付 |
| ③ 封面 | `douyin-cover-generator` | 成片封面；**系列自建风格时以风格总纲为准**，封面 skill 只当渲染引擎 |

安装见合集仓库根 README：clone 一次后把 `skills/<name>/` 链接进所用工具的 skill 加载目录即可。

## 何时用 / 何时不用

- **用**：素材或主题体量超过单集容量（>180s 讲不完 / >1 个核心心智模型）；用户明说"系列、合集、多集、分集"；**要围绕一本书做阅读指南/陪读/科普**
- **不用**：一集讲得完的主题直接走单集流程，别为拆而拆

## 工作流（8 步）

```
Step 1 体量判断 → Step 2 风格总纲（先于拆分！）→ Step 3 拆分逻辑
   → Step 4 链接强度 → Step 5 落盘规划 → Step 6 逐集制作
   → Step 7 交付样板集 → Step 8 指导后续章节（导师模式）
```

> **只做总览也是完整交付**：Step 1–5 做完规划与风格，Step 6 只做第 1 集（样板），Step 7–8 把模板、引擎与导师手册交给后来者。剩下 16 集由别人按样板做——这比你自己做完 17 集更常见，也更符合"系列可维护"的目标。

### Step 1 · 体量判断与素材解析

1. **抓全文**
   - 网页：WebFetch 优先；微信等反爬页面用 curl + 浏览器 UA 抓 HTML，再用 Python 去标签抽正文（正则剥 `<p>/<br>` 与标签，unescape），存为 md
   - **EPUB/书籍**：不要整本读。用 Python `zipfile` 解包 → 读 `content.opf` / `toc.ncx` 拿章节清单 → 逐章 xhtml 去标签转 md → **对每章只做"结构测绘"**（小标题 + 首段 + 含数字的句子），产出 `tmp/book_digest.md` 再据此规划。EPUB 的 `chapterN.xhtml` 常是"篇首页"，真正的章在 `chapterN_000X.xhtml`，编号与书内章号**通常对不上**，必须靠 `<h2>` 文本重建映射
   - **PDF/扫描件**：先 OCR 或转文本，确认中文可搜索，再走上面的测绘流程
2. **估算体量**：中文字数 × 0.06~0.08 s/字 ≈ 讲透所需秒数。>180s 即进入系列流程
3. **列原始章节清单**：章/节标题 + 一句话主旨 + 体量占比 + **硬数字个数**（后面重组的原料，也是 Step 5 资料分级的依据）
4. **书籍类额外一步：分清事实、数据、主张**。书里的三类内容可信度完全不同：
   - **史实**（发生了什么）→ 与第二来源交叉核对
   - **数据**（多少人、多少钱）→ **必须回原始出处**，书本身是二手整理
   - **作者主张**（"这是最好的时代"）→ 视频里必须用「作者认为」，不得讲成客观事实
   同时**先做一次书内自洽检查**：同一事件在书的不同章节是否给了不同数字（常见！见 `references/case-study-book-guide.md`）。发现冲突立即进勘误台账，别等做到那一集才发现。

### Step 2 · 系列风格总纲（**新增，必须早于拆分**）

**为什么在拆分之前**：风格一旦定下，拆集的粒度会被它反向约束（比如"档案室"语法要求每集都有一个可查证的年份区间；"手绘卡通"则允许更抽象的主题）。先拆后定风格，返工的是全部集。

产出两份文件，放在系列根目录：

| 文件 | 内容 | 消费者 |
|---|---|---|
| `系列风格总纲.md` | 人读：为什么是这个风格、八条铁律、幕结构、封面构图、反例清单 | 制作方、审阅方 |
| `style-tokens.json` | 机器读：色板、字体栈、字号、版式坐标、动效参数、字幕与封面规范 | 工程代码、封面脚本（**禁止手抄色值**） |

**风格必须从主旨推导，不能凭喜好选**。做法：把主旨拆成 3 句话，每句强制翻译成一条视觉决策，再反推出"不能做什么"。

> 实战示范（《以日为鉴》，详见 `references/case-study-book-guide.md`）：
> - 主旨"这是账本不是史诗" → 档案纸 / 表格线 / 卷宗编号 / 校对印
> - 主旨"记录可查证的年份与数字" → 等宽数字 + 表格承托 + 页眉卷宗号
> - 主旨"讲留在原地的人" → 剪报、手写批注、贴纸（"某个人整理过的材料"）
> - **反推红线**：不能可爱化（题材会失重）、不能发光（未来感破坏年代感）、不能极简（抽离掉扎人的细节）

**风格总纲必须回答的 10 个问题**（缺一个都会在制作时被各集"自由发挥"）：

1. 一句话世界观（这系列是什么语法？）
2. 三个反复出现的母题物件（系列识别符号）
3. 色板（含**唯一强调色**与其面积上限）
4. 字体层级（数字用不用等宽？标题衬线还是黑体？）
5. 版式网格（哪些区域永久占位、永不被内容压）
6. 动效白名单（入场动作只能有几种？各自参数）+ 黑名单
7. 幕结构模板（几幕、每幕多少秒、每幕承担什么）
8. 封面策略（构图、四件套、缩略图自检标准）
9. **每集继承清单（DoD）**：打勾才能开工
10. 反例清单（哪些做法一律退回）

**封面策略要单独想清楚"在信息流里怎么被看见"**：如果赛道里 90% 是暗场发光，那么整张亮纸就是断点优势；反之亦然。**别默认沿用上个系列的封面语言**。

**必须出样张验证**：风格总纲写完，先渲 1 张关键帧 + 竖/横封面各 1 张，**逐张看图**（含 1/4 缩图），确认后再写拆分文档。样张不过关的总纲，做 17 集就是 17 次返工。

### Step 3 · 拆分逻辑（本 skill 核心）

四条原则，按序执行：

1. **不按章节机械切**：章节体量常不均（有的章值 3 分钟、有的值 30 秒），机械切必碎
2. **按认知弧重组**：把章节映射到学习顺序而非作者写作顺序。技术类常用弧：世界观（为什么）→ 结构（是什么）→ 机制（怎么给/怎么收）→ 原理（怎么快）→ 实战（怎么查）；叙事/社科类可用：钩子 → 破题 → 展开 → 收尾
3. **每集一个可独立成立的心智模型**：检验法——"能否用一句话说清本集让观众学会了什么？"说不出就继续合并或拆分
4. **番外机制**：与主线不咬合但内容量够的章节（进阶/工具/历史八卦）做番外，不进主线、不影响完整性

**书籍类特例**：作者已经排好顺序的书（尤其是"总—分—总"结构的社科书），**忠于原书章节边界**往往比重组更好——重组会破坏作者精心搭的认知弧。判断法：逐章问"删掉这一章，后面还看得懂吗？"都答"看不懂"就说明顺序是承重的，别动。

集数粒度参考：

| 素材体量 | 拆分 |
|---|---|
| ≤180s 讲完 | 1 集（不走本 skill） |
| 5-8 个可独立心智模型 | 5-6 集主线 + 可选番外（最常见） |
| 高度连续不可分（连续推导等） | 2-3 集，接受单集偏长（≤240s），减少链接负担 |
| **书籍做"阅读指南/陪读"** | **一章一集**（薄章合并、厚章可拆），总量控制在 12-20 集 ≈ 40-60 分钟 |

**"讲透"与"导读"的取舍**：按 0.06~0.08 s/字，一本 10 万字的书"讲透"要 35-55 集。**除非用户明确要完整改编，否则按导读密度做**——每集只讲主线 + 关键数字 + 最反直觉的结论，把细节主动留给读者。这个取舍必须在规划文档里写明，否则做到第 8 集才发现"讲不完"。

### Step 4 · 链接强度决策

三档光谱，默认推荐中间档**模块化系列（Modular Series）**：

| 档 | 特征 | 适用 |
|---|---|---|
| 完全独立 | 各集零交叉，重复铺垫 | 各集主题差异极大、消费完全单点 |
| **模块化系列（推荐）** | 单集能独立看懂，合起来成套 | 绝大多数情况 |
| 强连载 | 必须按顺序看 | 强情节/连续课程 |

判断依据：单集转发场景（公众号/B站/群分享）要求"可独立看懂"；系列沉淀要求"有追更线索"——两档都要，取中间。

模块化系列的三件链接器（轻耦合，缺一会散）：

1. **共享世界（主链接）**：统一视觉 IP + 一张贯穿全系列的主图。每集开头 2s 主图点亮本集所在位置，结尾回主图。观众一眼知道自己在体系哪一层，且不依赖前集
   - 例（技术）："内存大厦"——上层虚拟楼层 / 中层 MMU 翻译官 / 下层物理内存
   - 例（社科/书籍）："40 年时间轴"——底部常驻，每集点亮本集年份区间
2. **回指（弱链接）**：用到前集结论时一句话复述，不逼观众补课（例："上集说过进程拿的是假地址——那它落在哪块真内存上？"）
3. **预告与菜单（引导）**：片尾 5s 下一集预告；简介区放系列目录 + **2-3 条推荐观看路径**（完整线 / 某类人群线 / 某条主题闭环线）

### Step 5 · 落盘系列规划（开工前第一份文档）

创建 `<项目根>/<系列名>/`，写 `系列规划.md`（复制 `assets/系列规划-模板.md` 改）。必含六块：

1. **为什么值得做成系列**（素材的独特性，2-3 条，防止后期自己都忘了当初的判断）
2. **体量测算与分集结论**（含"讲透 vs 导读"的取舍）
3. **集目清单**：# / 片名 / 素材来源 / 认知弧位置 / 定位一句话 / **资料分级**
4. **链接强度与三件链接器**（含推荐观看路径）
5. **资料分级与扩展规则**（见下，**本次新增的核心机制**）
6. **全局约定 + 勘误台账 + 制作进度**

#### 资料分级与扩展规则（本次新增）

素材是现成的，但**素材的详略不等于视频的详略**。每集制作前先定级，再决定扩不扩展：

| 分级 | 判据 | 处理方式 |
|---|---|---|
| **A 级 · 足够** | 单章 ≥5,000 汉字，且 ≥8 个可溯源硬数字 | **不扩展**。足够充实时硬加料，只会让视频偏离原意、增加溯源负担。明确写"本集不扩展" |
| **B 级 · 偏薄** | 单章 3,000–5,000 汉字，或硬数字 <8 个 | **定点补 1-2 处**，且只能补指定类型（政策原文 / 官方统计口径 / 同期媒体记录） |
| **C 级 · 不足或失效** | 单章 <3,000 汉字，**或结论依赖会过期的数据** | **必须扩展**，且要标注"本书成书于 X，此处已更新至 Y"；扩展量不设上限但逐条溯源 |

**C 级最容易漏判的是"时效性衰减"**：二手材料的"当下判断"（"今年是元年""现在正是窗口期"）过了 12-18 个月就会失真。这类章节**按 C 级处理**，必须重查数字并补最新进展。

**扩展的硬边界**（写进每集分镜的"制作红线"）：

- 不得引入素材中未提及的人物/事件作为叙事主线
- 不得把"作者观点"讲成"客观事实"
- 扩展材料与原文冲突时，以可溯源的一方为准，并在**做成片之前**进勘误台账
- 版权口径：单集引用原文总量 ≤ 全片字幕字数的 15%，且逐条标注出处

### Step 6 · 逐集制作（双线模式：主线验收 + 子代理制作）

每集执行六步：

1. **主线调研**：WebSearch 交叉验证 2-4 轮，关键数字必须溯源；查不到写"示意/约"，绝不杜撰。产出 `research/` 留痕 + 本集 `调研材料.md`（核心问题 / 人话版概念 / 数据点表带溯源 / 金句候选 / 叙事线 / 勘误引用 / **本集资料分级与扩展记录**）
2. **主线写（或审）分镜脚本**：每幕一行（时间码/章节/画面要点/字幕金句），幕数按风格总纲的幕结构模板；钩子在前 15s；系列元素三件套（点亮/回指/预告）；附**硬数字核对清单**与**制作红线**
3. **写 voice-ready 字幕（即使当下不配音）**：见下。**这一步不能省**——后期配音是常态，字幕结构错了就要重排整集时间轴
4. **派 SubAgent 制作**：每集一个子代理，封闭在本集文件夹。prompt 必须自包含：风格总纲与 `style-tokens.json` 的路径、视频 skill 的 SKILL.md 路径、参考工程路径、环境命令（node/python/渲染/合成/precheck 全路径）、调研材料与分镜位置、自检要求、汇报格式。**一次可并行 2 集**（全量渲染阶段抢 CPU，仅降速不致命）
5. **主线验收**（不照抄子代理报告，独立复跑）：
   - precheck 静态自检退出码 0
   - 关键帧逐张看过并签收（**机械体检拦不住叠字、元素互压、语义错位**）
   - ffprobe 规格：时长在区间内 / 1080p / 24fps / H.264 / 无音轨
   - 成片抽帧非空白（读图不可用时 Pillow：非纸底像素 >2% 判非空白，暗像素 <0.5% 判空）
   - 分镜硬数字与调研材料逐项一致
   - **风格抽查**：随机抽 5 帧，对照风格总纲逐条核（母题物件在不在、强调色面积、字体层级）
   - 产物全部归位，系列根目录外无散落
6. **汇报用户**：成片 + 每幕一句话 + 遗留项

### Step 7 · 交付「可复制的样板集」（**v2.1 新增，强烈建议**）

**只做总览，剩下的集交给别人做**——这是最常见的真实场景。这时你的产出不是"17 集"，而是**1 个样板集 + 3 份可复制的说明**。

为什么必须有样板集：文档描述风格会失真，**代码不会**。后来者读十页规范，不如抄一遍能跑的工程。

样板集必须包含（缺一不可）：

| 文件 | 作用 | 给谁看 |
|---|---|---|
| `scenes.js` + `archive.js` + `framework.js` + `video.html` | 能直接跑起来的完整工程 | 想复制的人 |
| `运镜与制作思路.md` | **为什么**这么画（逐幕讲设计决策 + 踩坑记录） | 想做对的人 |
| `视频分镜脚本.md` | 画什么（每幕一行） | 想照格式的人 |
| `字幕.srt` | voice-ready 的实例 | 想对齐语速的人 |
| `调研材料.md` | 数据从哪来（含勘误红线） | 想核数据的人 |

配套产出三份「留给后来者」的模板与方法（本 skill 的 `assets/` 与 `references/`）：

- `assets/集目录模板.md`：一个完整集目录长什么样 + 组件速查表 + 命令序列 + 实际数据基准
- `references/style-engine.md`：**风格引擎三层结构**（tokens → 引擎 → 场景），怎么让 N 集不各画各的
- `references/mentor-guide.md`：**导师手册**——派单任务书六要素、四道验收闸门、常见偏离与处理、给"学生"的一段话

**关键认知**：风格一致性是**工程问题**，不是纪律问题。靠文档约定管不住手抄色值，要靠 API 强制——把字幕坐标、色值、动效全部封进组件，场景文件里根本写不出来。

### Step 8 · 指导后续章节（导师模式）

分工原则：**方向和验收不能派，执行可以派**。

- 导师负责：系列规划、风格总纲、**样板集**、分镜预审、关键帧审查、成片终验
- 可派出去：单集调研、分镜初稿、工程实现

派单任务书必须自包含（六要素）：绝对路径 → 必读文件顺序 → 本集具体输入（含勘误红线）→ 硬性禁止项 → 交付物清单 → 自检要求与汇报格式。

**四道闸门**（成本从低到高，越早拦越省）：

1. **分镜预审**（改文档 10 分钟）——8 幕各有独立作用？每幕的强调色焦点是什么？字幕总字数对不对？
2. **静态自检**（precheck 退出码 0）——只证明代码没写错
3. **关键帧视觉审查**（**核心闸门**）——签收记录绑工程指纹，改一行代码签收就作废
4. **成片终验**（独立复跑 ffprobe + 抽帧 + 硬数字逐项对）

**导师的验收不是重跑，是抽查**：签收文件在不在、指纹是不是最新、自己抽 2–3 帧看。对方说"审过了"但没有签收文件，视为没审。

#### Voice-ready 字幕规范（新增，即使当下无配音也要遵守）

配音管线通常是"**按字幕槽位合成 → 超长则加速（有上限）→ 仍超则硬裁**"，并且对齐后会**拉长整片**（实测：原稿 172.0s → 配音版 198.9s，逐幕放大 1.07–1.28 倍）。因此：

| 规则 | 值 | 原因 |
|---|---|---|
| 朗读语速基准 | **5.0 字/秒**（区间 4.6–5.5） | 留出余量，保证 TTS 自然语速（约 6 字/秒）不会触发加速上限 |
| 单条字数 | **12–24 字**，硬上限 28 | 超过 28 字，3.5s 槽位将要求 ≥8 字/秒，必然被硬裁 |
| 单条槽位时长 | **2.6–4.5s**，按 `字数 ÷ 5.0` 估算 | 槽位略长于 TTS 自然时长，留静音最自然 |
| 幕边界 | **必须落在字幕边界上** | 配音对齐按幕缩放，切在字幕中间会导致该幕内错位 |
| SRT 格式 | UTF-8 无 BOM、条间一个空行、编号连续 | 对齐脚本按 idx 组装 |
| 声画链顺序 | **无声母版 → 配音 → BGM** | 配音会改变时长；先合 BGM 等于把拍点算在作废的时间轴上 |

**如果素材是知识密度高的社科/技术内容**，注意每幕的"信息量 ÷ 时长"：读者要时间消化数字。硬数字密集的幕，槽位按 5.5 字/秒算更稳。

## 硬性规则

1. 单集 ≤180s（番外可短；风格总纲可授权扩至 240s）；钩子必须在第 1 幕前 15s
2. **风格总纲必须先于拆分**，且必须出样张验证
3. **全系列共用一份 `style-tokens.json`**，禁止各集手抄色值/字号
4. **资料分级先行**：A 级明确写"不扩展"，C 级必须扩展并标注更新时间
5. 关键数据三层溯源：成片 → 调研材料 → research/ 原始来源
6. 史实/数据/主张三分：**作者主张必须标"作者认为"**
7. 来源错误一律进勘误台账并在成片修正——**绝不让错误进视频**
8. 每集每个专业概念配类比，初中生能复述大意
9. 字幕按 voice-ready 规范写，幕边界落在字幕边界上
10. 产物归位：系列根目录外无散落文件
